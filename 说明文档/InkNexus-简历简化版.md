## 一、推荐版（默认用这版）

**项目名称**：墨枢 InkNexus —— 图书电商微服务系统

**技术栈**：Spring Boot、Spring Cloud Alibaba（Nacos / Gateway / OpenFeign）、MyBatis-Plus、MySQL、Redis、RabbitMQ、Vue 3

**项目描述**：

1. 采用微服务架构，将系统拆分为用户、图书、购物车、库存、订单、支付等服务，网关统一完成 JWT 登录鉴权与用户身份透传，使用 Nacos 做服务注册与配置中心。
2. 实现下单-支付-库存核心流程：下单时通过数据库条件更新（`WHERE stock >= n`）扣减预占库存防止超卖，通过唯一索引防止重复提交产生重复订单。
3. 支付成功、库存确认/释放等跨服务操作通过 RabbitMQ 异步事件解耦，消费端做幂等处理；订单超时未支付通过延迟消息自动关单，并以定时任务兜底，保证订单与库存数据一致。
4. 图书查询接入 Redis 缓存，针对缓存穿透、击穿、雪崩问题分别采用空值缓存、互斥重建、过期时间打散处理。
5. 接入通义千问大模型实现智能客服，支持 SSE 流式回答，可通过工具调用查询图书和本人订单；编写 81 个单元测试覆盖防超卖、幂等、缓存等核心逻辑。

**这版守得住的边界**：每条被追问第一层都有准备好的答案；第二层（Lua 解锁、eventId 去重表、队头阻塞）在《面试问答准备》里都有，被问到再展开。

## 二、更保守版（细节还没吃透 / 面试临近时用）

**项目描述**：

1. 基于 Spring Boot + Spring Cloud Alibaba（Nacos、Gateway、OpenFeign）的图书电商系统，按业务拆分为多个微服务，网关统一 JWT 鉴权。
2. 实现下单、支付、库存管理完整流程：数据库条件更新防止超卖，唯一索引防止重复下单，订单超时未支付自动关单并归还库存。
3. 通过 RabbitMQ 异步处理支付成功与库存变更事件，消费端做幂等设计，防止消息重复消费导致数据错误。
4. 使用 Redis 缓存热点图书数据，处理缓存穿透、击穿、雪崩问题；编写 81 个单元测试覆盖核心业务逻辑。

> 5. 接入大模型 API 实现图书咨询助手，支持流式输出。

## 四、自检规则（每次改简历过一遍）

1. **两分钟测试**：简历上留下的每个名词，做"是什么 → 为什么 → 怎么做"不看稿讲 2 分钟。讲不出来 → 降级成大白话或删掉。
2. **钩子要主动埋**：简历钩子少没关系。面试时在回答里主动埋一个你最熟的钩子（比如讲完下单主动补一句"这里我还处理了重复提交的场景"），把追问引到你准备最充分的地方——比被动等面试官挑你接不住的词强得多。
3. **压测数字**：在跑出真实数据之前，简历和口头都不要出现任何 QPS/P95 数字（防穿帮清单第 1 条）。
4. **删掉 ≠ 不会**：被删的术语（eventId 去重、Lua 解锁、Confirm、队头阻塞）是你的第二层弹药，被追问时再拿出来，正好按面试问答准备文档的题号展开。
